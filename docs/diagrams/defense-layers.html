Five layers between a client's data and the LLM

Detection models miss things, so no single layer is trusted on its own. Every example below is a real case from this project's tests or demo runs.

1
DetectPresidio + spaCy NER, format patterns with context words, labelled fields
Catches Name: Amit Sharma — spaCy's small model missed it; the Name: label rule didn't. An unformatted SSN counts only with a word like "social security" nearby.
2
Merge overlapstwo recognizers disagree on a span → mask the union, keep the most specific label
Catches A date match starting one character before an Aadhaar number. Keeping just one span used to leave the other's tail in clear text; the label is now the identifier, not DATE_TIME.
3
Known-value sweepany value the vault already holds is re-tokenized before sending
Catches what is priya sharma's ssn? — NER misses the lowercase name in the question, but it was tokenized at ingest, so the sweep sends <<PERSON_01_..>>.
4
Block hard identifiersSSN, Luhn-valid card, Aadhaar, PAN, email or phone left outside a token
Catches An SSN in the prompt with redaction switched off entirely (a test does exactly this): the request is refused with HTTP 422 and nothing is sent.
5
Auditevery redaction and every egress, allowed or blocked
Records Entity types, tokens and counts only. An earlier version logged a 50-character preview that still held unreplaced PII; a test now asserts no detected value ever reaches the log.
What still gets through: a value nobody has seen before, with no recognisable shape, that NER misses at ingest and again in the question (an unusual name in free text, say). No automated system can promise zero; this one narrows it to that case and records every request that leaves.
